# 代码生成 {#code-generation}

## 概述 {#overview}

FusionInfer 的 API 类型定义在 `api/core/v1alpha1/*_types.go` 中。DeepCopy 方法、client-go、CRD 和控制器的 RBAC 角色都根据这些类型及其中的标记生成，不需要手写。

生成的 Go 文件开头都有 `// Code generated by <生成器>. DO NOT EDIT.`，生成的 CRD 带有 `controller-gen.kubebuilder.io/version` 注解。不要手动修改这些文件：下次生成时改动会被覆盖，CI 也会检查出生成的文件和源码不一致。

## 自动生成的文件 {#generated-files}

| 路径 | 生成器 | 命令 |
| --- | --- | --- |
| `api/core/v1alpha1/zz_generated.deepcopy.go` | controller-gen（`object`） | `make generate` |
| `client-go/clientset/` | client-gen | `make generate` |
| `client-go/listers/` | lister-gen | `make generate` |
| `client-go/informers/` | informer-gen | `make generate` |
| `client-go/applyconfiguration/` | applyconfiguration-gen | `make generate` |
| `config/crd/bases/*.yaml` | controller-gen（`crd`） | `make manifests` |
| `config/rbac/role.yaml` | controller-gen（`rbac`） | `make manifests` |

`make generate` 先用 controller-gen 生成 DeepCopy，再调用 `hack/update-codegen.sh`，由 Kubernetes [code-generator](https://github.com/kubernetes/code-generator) 生成 `client-go/` 下的代码。`Makefile` 会从 `go.mod` 读取 `k8s.io/api` 的版本，并使用同一版本的 code-generator。controller-gen 的版本由 `Makefile` 中的 `CONTROLLER_TOOLS_VERSION` 固定。两个工具都会在第一次运行时自动下载。

## 修改 API 后的流程 {#changing-the-api}

1. 修改 `api/core/v1alpha1/*_types.go` 中的字段或标记。
2. 运行 `make generate manifests`，重新生成代码和清单。
3. 运行 `make test`。它会先运行 `make manifests` 和 `make generate`，让测试用上最新的 CRD 和生成代码。
4. 把源码和生成的文件放在同一个 commit 中提交。

CI 的 Unit Tests job 会重新执行 `make generate` 和 `make manifests`，再检查工作区有没有变化。只要生成的文件和源码对不上，CI 就会失败，并提示：

```text
Generated code or manifests are not up to date. Run 'make generate manifests' and commit the changes.
```

遇到这个错误时，在本地运行 `make generate manifests`，然后提交产生的变化。

## 控制生成的标记 {#generation-markers}

生成器根据 Go 注释中的标记（marker）决定生成什么。下表列出这个仓库常用的标记，完整列表见 [kubebuilder 标记文档](https://book.kubebuilder.io/reference/markers.html)。

| 标记 | 写在哪里 | 作用 |
| --- | --- | --- |
| `+kubebuilder:object:generate=true` | `package` 声明上方（`groupversion_info.go`、`doc.go`） | 为包中的所有类型生成 `DeepCopy` 和 `DeepCopyInto` |
| `+groupName=fusioninfer.io` | `package` 声明上方（`groupversion_info.go`、`doc.go`） | 设置 API group，也决定 client 的方法名 `FusioninferV1alpha1()` |
| `+kubebuilder:object:root=true` | 顶层资源类型及其 List 类型 | 额外生成 `DeepCopyObject`，使类型实现 `runtime.Object` |
| `+kubebuilder:resource:scope=Namespaced`、`scope=Cluster` | 顶层资源类型 | 决定 CRD 是 Namespaced 还是 Cluster-scoped |
| `+kubebuilder:subresource:status` | 顶层资源类型 | 为 CRD 开启 status subresource |
| `+genclient` | 顶层资源类型 | 生成 typed client、lister、informer 和 apply configuration |
| `+genclient:nonNamespaced` | Cluster-scoped 资源类型 | 生成不带 Namespace 参数的 client |
| `+genclient:noStatus` | 没有 status 的资源类型 | 不生成 `UpdateStatus` 和 `ApplyStatus` |
| `+kubebuilder:validation:*`、`+required`、`+optional` | 字段或类型 | 写入 CRD 的 OpenAPI 校验，其中 `XValidation` 生成 [CEL 校验规则](https://kubernetes.io/docs/tasks/extend-kubernetes/custom-resources/custom-resource-definitions/#validation-rules) |
| `+kubebuilder:rbac` | 控制器代码 | 生成 `config/rbac/role.yaml` 中控制器需要的权限 |
